C[i][j] = Σ A[i][k]·B[k][j] — dot row i of A against column j of B. Nothing about C[i][j] depends on any other row of A, any other column of B, or how many other output rows exist.

Row 0 came out identical either way — same numbers, same sums, same order of operations, one row at a time. So here's the question: how could two calls to the same matmul, on the same GPU, computing that exact same row, ever give a different answer?
# same shape of question, at real size B = 2048 D = 4096 a = torch.linspace(-1000, 1000, B*D).reshape(B, D) b = torch.linspace(-1000, 1000, D*D).reshape(D, D) # matrix-vector: take row 0 first, then multiply — just like the left demo above out1 = torch.mm(a[:1], b) # matrix-matrix: multiply the full batch, then take row 0 — just like the right demo above out2 = torch.mm(a, b)[:1] percentage_difference = ((out1 - out2).abs() / out1.abs()) * 100 # on real GPU hardware: percentage_difference.max() is nonzero. # out1 != out2, even though they're mathematically the same row.

With toy 4×3 integers, both panels above run the exact same additions in the exact same order, so of course they agree. At B = 2048, D = 4096, in fp16/bf16, they don't run the same additions in the same order — the batch size changes which GPU kernel gets picked, and different kernels group this same sum differently.
