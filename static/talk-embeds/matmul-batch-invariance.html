Matrix multiply is deterministic.
Batch-invariant, it is not.

same weights · same request · different batch size
# but not batch-invariant B = 2048 D = 4096 a = torch.linspace(-1000, 1000, B*D).reshape(B, D) b = torch.linspace(-1000, 1000, D*D).reshape(D, D) # matrix-vector: take the first row of the batch, then multiply out1 = torch.mm(a[:1], b) # matrix-matrix: multiply the whole batch, then take the first row out2 = torch.mm(a, b)[:1] percentage_difference = ((out1 - out2).abs() / out1.abs()) * 100

Our request's output depends on the parallel user requests sitting in the same batch — not because anything leaks across requests, but because the forward pass lacks batch invariance. Change the batch size, and the exact same row of output can come back different.

Matmul kernels are run-to-run deterministic — same batch size, same answer, every time. But mathematically, row 0 of the output should depend only on row 0 of the input and the weight matrix — never on how many other rows are riding along. Empirically, it does.
